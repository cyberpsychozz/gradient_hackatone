# Идеи решений — Gradient Hackathon (Mars Rover 0.16.0)

> Статусы идей: **🟡 гипотеза** (нужна проверка), **🟢 проверяемая** (есть метрика и план), **🔴 отменено** (противоречит коду). Ссылки на файлы — по репозиторию `environment/`. Обязательные правила заезда — [run_rules.md](run_rules.md), находки — [exploits.md](exploits.md), миры — [worlds.md](worlds.md).

## 0. Что мы имеем: сводка контракта и метрики

- **Метрика:** медиана максимальной дистанции по 48 заездам (9 типов трасс + 7 последовательностей зон × 3 варианта мира), по 300 с модельного времени, минус первый метр. Откат назад не уменьшает максимум (`best_progress_x_`, `environment/cpp/src/env.cpp:104`).
- **Формат:** ZIP с `Dockerfile`/`train.py`/`README.md`, обучение 2 ч на ~15 ГиБ видеопамяти, на выходе `/output/policy.onnx`.
- **Модель:** 7 входов (observation[160], previous_action int64, previous_reward, previous_done, trial_progress, trial_start, memory[M≤4096]), выходы logits[31] + next_memory. Выбирается argmax; вероятности не нужны.
- **Граф:** 1…1024 узлов ONNX, opset 17, ограниченный список операций (без ConstantOfShape, Or, Log, Cos, ConvTranspose и т.п.). Все 7 входов обязаны присутствовать. Массивы ≤ 8 М элементов, суммарно ≤ 64 М.
- **Действие** удерживается 8 шагов по 1/60 с; переключатели (лидар, панель, режим привода, подъём, винт, поршни) срабатывают по фронту, для повтора нужно сначала дать команду без них.
- **Среда:** 160 наблюдений, 31 команда, стартовая энергия 100, ёмкость 130, награда `progress_delta − 0.01·energy_cost − штрафы` (`environment/cpp/src/reward.cpp:8`).
- **Локальная сборка ≠ закрытая:** callbacks эффектов биомов 8–19 в исходной физике отключены (`environment/cpp/src/physics/step_wheels.inc:205`, `step_dynamics.inc:2`), включены только для ID 20–39. В закрытой проверке действует сборка организаторов. Локальные результаты по биомам 8–19 нельзя переносить как есть.
- **Распределение сложности в тренировке отличается от оценки:** `terrain.length=420` против фактических ~20 км рельефа даёт слишком длинный лёгкий старт; оценка стартует с максимальной сложности (`exploits.md`).

## 1. Идеи по обучению и пайплайну

### 1.1 Экспорт и проверка контракта 🟢
- Экспортировать модель **сразу после инициализации весов**, потом после каждого удачного этапа (`run_rules.md`). Ошибка экспорта в конце 2-часового обучения = нулевой результат.
- Прогонять `check_policy.py` в каждом чекпоинте; использовать только разрешённые операции — запрещено даже то, что PyTorch добавляет неявно (например, `ConstantOfShape` при `expand`).
- Проверить, что **batch-измерение** называется `batch` и модель проходит батч 48 (сервер гоняет 48 заездов одновременно).
- Составить локальный конвейер: сборка → `make check` → `train.py` (короткий) → `export` → `check_policy.py`.

### 1.2 Распределение миров для тренировки 🟡
- Закрытая проверка использует максимальную сложность с самого начала. Значит тренировочное распределение стоит сдвинуть: `difficulty_safe_fraction_min=max=0.0`, `difficulty_exponent` меньше (чтобы сложность нарастала быстрее), либо своя генерация цепочек.
- Проверить, как меняется результат одной и той же политики при `difficulty_safe_fraction` 0.02 vs 0.0 на отложенных сидах. Метрика: медиана max-дистанции.
- Добавить в пул больше `fixed_biome_id` миров с фазами (20–39), т.к. именно на них действуют физические эффекты.

### 1.3 Куррикулум 🟡
- Начать с G1–G2 (20–25), вводить G3 (26–33), затем G4–G5 (34–39) и леджевые 13/38.
- Учитывать, что леджевые миры (13, 38) генерируют разрывы только при `difficulty ≥ 0.08` по `Terrain::difficulty_at` (`world_layout.cpp:414`); в локальной тренировке с safe_start=400 м они почти не появляются — нужен сдвиг safe_fraction или свои трассы.
- Метрика продвижения куррикулума: медиана по фиксированным сидам внутри каждого грейда.

### 1.4 Reward shaping (только обучение) 🟢
- Шейпинг не попадает в оценку, но может ускорить обучение. Через monkey-patch `MarsRoverEnv.step` (`exploits.md`), но аккуратно: это меняет оптимум политики. Шейпить под цель «ехать вперёд при живом аккумуляторе», а не под «не тратить энергию».
- Примеры сигналов из `debug_info()`: `energy_cost_rate`, `damage`, `vx`, `hazard`, `hazard_ahead`, `ground_height`, `speed`.
- `hazard_ahead = biome_by_id(zone).hazard_at(step_index + 55)` — доступно уже сейчас; можно штрафовать вход в активную фазу (окна плавления, импульсы).
- Не использовать поля, которых нет в официальном observation (hazard и пр.) — модель должна решать по 160 наблюдениям.

### 1.5 Валидационный харнесс 🟢 (первый шаг)
- Скрипт: фиксированный набор сидов (например, 32 сида × 40 биомов), гоняет заезды политикой (сначала случайной, потом PPO), считает: медиану max-дистанции, долю падений/переворотов, средний расход энергии, где застревает.
- Отдельно: цепочки зон по `chain_biomes=true` (как в заезде), т.к. 9+7 типов трасс — смесь биомов.
- Это же даст измеренные грейды вместо предварительных в `worlds.md` (пункт 3 в `ideas.md`).

## 2. Идеи по архитектуре модели

### 2.1 Базовая (старт) 🟢
- Текущая `Policy` (`environment/model.py`): encoder → GRUCell → actor/critic. 1.5M фреймов, 64 envs, frame_skip=8, hidden 128.
- Масштаб можно увеличить: hidden 256–512, memory 64–256 (не обязательно 4096; ограничение — скорость инференса 48 envs и вес ≤32 МиБ).

### 2.2 Реакция на previous_done / trial_start 🟢
- `memory = memory * (1 − trial_start)` уже сбрасывается на новом заезде (`model.py:34`). Стоит дополнительно прокинуть `trial_progress` (доля времени) — экономия энергии на финишном отрезке или рискованная езда в начале.
- Учитывать `previous_done` — во время оценки заезды независимы (обычно 0), но поведение при перевороте/пацине важно для обучения.

### 2.3 Террайновые фичи из observation 🟡
- 24 точки высоты + 24 наклона впереди (0.5–24 м) — свёрточный одномерный блок поверх них (Conv1d 1-2 слоя) может научиться «видеть» уступы и кратеры лучше полносвязника. Conv разрешён списком операций.
- 8 дальних точек (80–103) появляются только после скана лидара — сеть должна выучивать «0 = неизвестно».
- Признак 7 (лидар-прогноз точки посадки) и 145–159 (режимы) — инженерно пересчитать в модель не нужно, но стоит проверить, что сеть их использует (можно добавить вторую головку, если позволяет формат — но выходов только logits/memory).

### 2.4 Вспомогательные головки/внутренние задачи 🟡
- Критик (value) уже есть в обучении. Можно добавить внутренний предсказатель следующего observation в loss (self-supervised) — увеличит качество энкодера.
- Проверить, можно ли в ONNX-граф добавлять лишние выходы: `check_policy.py` ждёт **минимум 3 выхода** (`environment/check_policy.py:15`), т.е. третий выход (например, value) в формате допустим; проверить на площадке.

### 2.5 Работа с дискретными командами 🟡
- 31 действие — это макросы битовых флагов с удержанием 8 шагов. Обучать политику на уровне макросов (как сейчас). Альтернатива: иерархия «высокоуровневое действие → примитив», но это риск по контракту.
- Важно научиться «отпускать» фронтовые команды: для лидара/панели нужна команда без неё после нажатия. Сеть с памятью это может выучить; проверить статистику удержаний в харнессе.

## 3. Поведенческие стратегии по биомам (для шейпинга и куррикулума)

| Биом (ID) | Проблема | Тактика-кандидат |
|---|---|---|
| sand (1) | пробуксовка, `sand_burial` при медленной езде | не останавливаться на песке; короткие рывки; избегать глубокого песка через лидар |
| ice (2, 29, 35) | низкое сцепление, холод | плавные газ/тормоз; тормоз раньше; обогрев при необходимости; на 35 ещё ветер 9 и теплообмен 2.4 |
| mud (3, 36) | вязкость, проседание | выбрать скорость не слишком низкую (глубокое проседание) и не слишком высокую (расход); на 36 фаза «прилипания» каждые 360 тиков |
| wind (4, 28, 37) | внешняя сила + моменты | контрруление; на 28/37 порывы синусоидальные — учиться синхронизации |
| low_gravity (5, 32) | длинные прыжки | мягкие посадки (safe_landing_speed 4.0, угол 0.55); сглаживать рельеф тормозом |
| liquid (7, 39) | бассейны, погружение | балласт (продувка повышает плавучесть на +1.10·air), винт (thrust при RPM>1800), поршни; не тратить энергию впустую |
| collapse_* (8,9,11) | окна плавления | `hazard_at` доступен в debug; активные окна: 8: 110/480, 9: 130/600, 11: 175/820. Проходить на умеренной скорости |
| rime/thermal (10,17,18) | холод/прилипание при низкой скорости | держать скорость выше порога (0.85 / 1.10 м/с), см. идею 4.2 |
| ledge (13, 38) | разрывы | рампы 2.8–3 м, ширина до 3.6 м; нужен точный прыжок: пре-лоад подвески + газ, лучше с лидаром-прогнозом |
| shear/lug (14,16,19) | периодические сдвиги/торможение | избегать высоких скоростей в фазе; фазы детерминированы по времени шага |
| gravity_shelf_lug (16) | тяжёлая фаза при v>0.30 | проезжать тяжёлую фазу медленно или ждать |
| сухие G1–G2 (20–25) | нет особых механик | базовая езда, тестирование передач |

### 3.1 Энергетический менеджмент 🟢
- Зарядка только при `solar_panel_requested && deployment≥0.999 && (stationary || airborne)` (`step_controls.inc:106`). При включённой панели **блокируется газ, тормоз, прыжок, поршни, балласт, винт** (`step_controls.inc:78-94`), но корпус продолжает двигаться по инерции и в воздухе.
- Тактика: разгон → выключить газ → включить панель → катиться/лететь и заряжаться → выключить → снова газ. Это «coast-and-charge».
- В биомах с высокой зарядкой (ice ×2.2–3, playa ×2.3–2.7, gravel ×1.55) выгодно стоять и заряжаться; в биомах с зарядкой ×0.05–0.16 (14,15,16,17,18,19,39) зарядка почти бесполезна — планировать энергию на проезд.
- Ёмкость 130, старт 100: запас всего 30. «Холостой» расход: только обогрев 0.15/с и мелкие потери; простоять можно долго.

### 3.2 Передачи и расход 🟢
- Расход топлива растёт с передачей (`kGearEnergyMul = 1.0…2.3`) и с `gear_index`; удержание газа в низкой передаче дорого. Стратегия: быстрый подъём передач на ровной поверхности, понижение на подъёме/грунте.
- `wheel_fuel` зависит от `|throttle|`, `clutch_engagement`, `speed²`, `viscosity`, `latent_energy_resistance`, `overspeed_cost_mul` (×10 при перекате 6-й передачи). Держать скорость ниже `gear_top_speed` 6-й, иначе расход ×10 (`step_wheels.inc:317-331`).
- Проверить: на ровной G1 трассе экономия при крейсерской скорости на 5-й vs 6-й передаче (метрика: метр/энергия).

### 3.3 Прыжки и уступы 🟡
- Прыжок: пре-лоад фазы 1 (зарядка пружины, 2.5/с энергии) → отпускание в фазе 2 (выброс, `0.06+0.15·charge` с). Прыжок требует отпустить кнопку (фронт). Подвесочный прыжок перед/зад (19–21) для переворота назад/вперёд.
- При угле >1.35 рад и активном прыжке работает восстанавливающий момент (16·recovery_state) — «самовосстановление» в воздухе (`step_powertrain.inc:371`).
- Винт (15): thrust 108·reserve·ready при RPM>1800, работает в воде с ценой ×1.0 (в воздухе ×1.25), только если корпус «вверх» (`step_dynamics.inc:91-104`). Кандидат для перелёта водоёмов и мягких посадок.
- Тяга (26/27): вертикальная сила 2.4·вес, 8.0/с — дорого; кандидат для леджевых прыжков и выхода из ям.

### 3.4 Лидар 🟢
- Пассивный обзор до 3 м всегда. Лидар 0.65·mul энергии, дальность 24·range_mul. При `range_mul ≤ 0.11` (14,16,19) скан не расширяет обзор, но стоит энергию (`exploits.md`) — команду лидара там не использовать.
- В биомах 13/38 (леджи) лидар дёшев (0.30 / 1.55) и важен для разрывов; при `lidar_range_mul=1` скан даёт 24 м — позволяет видеть ямы заранее.
- Лидар-прогноз точки посадки (obs[7], `update_lidar_landing`) активен только в воздухе — это ранний сигнал о приземлении, полезно на low_gravity/ledge.

## 4. Идеи эксплойтов (гипотезы — помечены, требуют измерения)

### 4.1 Зарядка в свободном полёте 🟡
`charging_active = requested && deployment≥0.999 && (stationary || airborne)` — в воздухе зарядка активна, и панель блокирует газ/тормоз, но не угловое движение и не подвеску. Если научиться прыгать/слетать с рампы с панелью — зарядка «бесплатна» по времени. Проверить: заряд за полёт vs расход на прыжок (2.5/с пре-лоад). Метрика: чистое изменение энергии за цикл «прыжок+полёт» на фикс. сиде.

### 4.2 Отрицательный energy_cost в горячей/холодной фазе 🟡
В `thermal_surge_relay` при почти нулевой скорости в горячей фазе и в `rime_quarry_dawn` вне холодной фазы код добавляет отрицательный `energy_cost` (`worlds.md`, `ideas.md:2`). Нужно измерить баланс: итоговая энергия до/после ожидания на фиксированных сидах с учётом всех остальных затрат (обогрев, обороты). Если чистый прирост положителен — стратегия «пережидать фазу стоя». Это среда организаторов, не локальная: проверить на обоих типах callbacks.

### 4.3 Панель создаёт подъёмную силу 🟡
`panel_force` при скорости >0.3 м/с: подъём ∝ v²·deployment (`step_powertrain.inc:332-340`). При большой скорости и развёрнутой панели марсоход «прижимается/поднимается» и получает момент — возможно, подъём на рампу или мягкое приземление. Также блокировка газа при панели — это «тормоз на панели». Измерить: проезд с панелью vs без на волнах (нормализованная скорость/энергия).

### 4.4 Винт как движитель на суше/в воздухе 🟡
Винт даёт силу вперёд и вне воды (цена ×1.25). На ровной трассе с панелью: газ + винт? Винт требует газ (`control.throttle>0`) и RPM>1800, т.е. работает только вместе с работающим двигателем — тогда зачем? Проверить на льду (низкое сцепление: колёса буксуют, винт добавляет тягу без буксования).

### 4.5 Поршни крыши для переворота 🟡
Поршни (17/21/22) создают силу до ~507·penetration при контакте с грунтом (8.0/с энергии) — потенциально позволяют перевернуть корпус после падения на крышу. `is_upright_on_wheels` требуется для снятия flip-латча. Идея: падение на крышу → поршни → восстановление → продолжение (метрика: доля восстановлений после флипа). Актуально для ledge-биомов.

### 4.6 «Прилипание» как источник залипания — обход через порог скорости 🟡
10 (`setpoint_rime_shelf`) и 18 (`rime_quarry_dawn`): при скорости ниже порога (0.85 / 1.10 м/с) добавляется сопротивление. Стратегия: никогда не опускаться ниже порога в этих биомах, даже на спусках (иначе расход на выезд). Проверить в харнессе: медиана дистанции при политиках с разными целевыми скоростями.

### 4.7 Стартовый спурт до лимита энергии 🔴/🟡
При энергии ≤0 гравитация ×4 и лимит скорости 0.35 м/с («limp mode») — т.е. севшая батарея почти гарантирует смерть. Значит приоритет — не допускать 0. Проверить: экономия на подъёмах vs риск.
